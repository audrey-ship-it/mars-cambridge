# 与 Partner 的协作与交接流程

## 1. 推荐的协作结构

项目的唯一事实来源是 GitHub 仓库，不是某一条 ChatGPT 对话，也不是任何一台电脑。

双方各自使用自己的 ChatGPT 账号、GitHub 账号、本地仓库或 Codex 工作区，以及 API/部署密钥。不要共享个人账号、OpenAI API Key、GitHub Token 或云服务密码。

## 2. ChatGPT Project 的用法

可以创建一个共享 ChatGPT Project，给 partner “编辑”权限，并放入：产品说明、PET/FCE 验收标准、命名和交互规则、当前里程碑、决策记录和待办列表。

共享 Project 用来共享上下文和讨论，不用来代替 GitHub。不要上传密钥、学生个人数据或整个媒体目录。两个人不能同步共同编辑同一条 ChatGPT 对话；各自开新对话或从已有对话分支，并把最终结论写回仓库文档或 GitHub Issue。

## 3. GitHub 工作流

1. 将 partner 加为仓库 collaborator；
2. 保护主分支，禁止直接 push；
3. 每项工作先建立 Issue，写明级别、Paper、Part、源文件页码和验收条件；
4. 每人使用独立分支，例如 `level/pet-reading-part1`、`level/fce-listening-part3`；
5. 一个 PR 只解决一个清晰主题；
6. PR 必须包含测试结果、截图、数据来源、已知限制；
7. 另一人审核后合并；
8. 合并后更新项目看板和题库完成矩阵。

同一时间不要两个人修改同一个巨型数据文件。优先按级别/试卷/Part 拆分数据模块，降低冲突。

## 4. Partner 首次接手清单

1. 克隆 GitHub 仓库；
2. 阅读 `README.md`、`AGENTS.md` 和 `docs/`；
3. 安装依赖并运行开发服务器；
4. 执行全部审计、lint 和 build；
5. 在 KET 中完整走一次：专项练习、模考、暂停恢复、交卷、查看错题、只重做错题、查词、生词打印；
6. 选择一个很小的 PET Part 做端到端试做；
7. 提交第一个 PR，由项目负责人审核后再批量录入。

## 5. 每次交接需要留下什么

- 当前分支和最后提交；
- 已完成项和未完成项；
- 可复现的测试步骤；
- 已知 Bug 和影响范围；
- 内容来源与授权状态；
- 需要另一人决定的问题；
- 数据/媒体是否已备份；
- 下一步唯一优先任务。

## 6. 推荐角色分工

你负责：产品优先级、视觉与交互验收、内容授权、最终发布决定。  
Partner 负责：PET/FCE 题库整理、录入、来源标记、逐题核对和第一轮测试。  
双方共同负责：PR 审核、正式题目答案抽查、上线合规与备份恢复演练。

角色可以调整，但同一套题的“录入者”和“最终核对者”应尽量不是同一个人。
