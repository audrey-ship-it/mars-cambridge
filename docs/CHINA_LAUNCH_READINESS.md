# 中国大陆上线准备清单

本文是产品和技术准备清单，不替代律师、当地主管部门或云服务商的正式意见。

## 0. 当前最高优先级阻断项

在公开发布之前，先解决内容权利。当前仓库含 Cambridge 考试题目、扫描图、音频和答案。必须逐项确认：

- 哪些材料许可数字化、公开传播及商业使用；
- 是否获得书面授权；
- “Cambridge”“KET/PET/FCE”等名称和标识如何合规使用；
- 网站不得让用户误以为它是 Cambridge 官方网站或官方评分系统；
- 无法证明使用权的材料不得进入正式生产环境。

## 1. 主体与服务边界

上线决定前必须明确：

- 网站主办主体是个人还是公司；
- 免费学习工具、付费内容、会员订阅还是在线培训服务；
- 是否服务未成年人；
- 是否收集手机号、家长信息、学习记录、录音或支付数据；
- 是否使用 AI 评分或把数据传到境外；
- 是否需要教育/校外培训等前置或专项审批。

这些答案会直接影响备案、隐私、未成年人保护和业务许可，不能等开发完成后再补。

## 2. 域名、托管与备案

- 购买由主办主体持有的正式域名；
- 如使用中国大陆服务器，先选择国内云厂商和接入商；
- 通过接入商办理 ICP 备案；如果是经营性互联网信息服务，进一步确认相应许可；
- 根据实际业务确认教育/校外培训是否需要前置审批；
- 网站开通后完成公安联网备案等适用手续；
- 页脚展示备案号、主体、联系方式、隐私政策和用户协议；
- 配置 HTTPS、国内 DNS、对象存储和 CDN。

## 3. 生产架构

当前 `localStorage + 静态资源` 只适合原型。正式架构建议拆为：

- 前端静态站点/CDN；
- 国内 API 服务；
- 关系型数据库保存账号、计划、作答、错题和生词；
- 对象存储保存音频、图片和授权材料；
- 统一身份认证、权限和会话管理；
- 管理后台处理题库版本、审核和发布；
- 日志、告警、性能监控和错误追踪；
- 自动备份与灾难恢复。

媒体迁移时保留稳定资源 ID，不在题库中散落云厂商完整 URL；由资源清单在部署时生成 CDN 地址。

## 4. 用户、隐私与未成年人

正式版至少提供：

- 隐私政策、用户协议、儿童/未成年人说明；
- 分目的告知收集哪些数据、为何收集、保存多久、与谁共享；
- 最少收集原则；
- 未满 14 周岁用户的监护人同意与专门保护机制；
- 撤回同意、注销账号、导出和删除个人数据；
- 麦克风、录音、相册等权限在使用时单独请求；
- 第三方 SDK/统计/客服清单；
- 数据泄露应急响应；
- 数据跨境使用前的专门评估。

第一版如不需要口语录音，就不要采集录音；如不需要真实姓名，就不要要求真实姓名。

## 5. 安全基线

- 开发、测试、生产环境隔离；
- 密钥进入 Secret Manager，绝不进入 Git；
- 账号密码安全存储，管理员启用多因素认证；
- 最小权限、操作审计、登录限流和异常告警；
- 依赖漏洞扫描和定期升级；
- 数据库不直接暴露公网；
- 每日备份、异地副本和季度恢复演练；
- 上线前进行权限、越权、注入、XSS、CSRF、上传和敏感信息测试。

## 6. 内容与教研后台

正式题库需要后台工作流：

`草稿 → 录入复核 → 教研复核 → 权利复核 → 测试 → 已发布 → 已下线`

每次发布保存版本、操作者、变更内容和回滚点。题库内容不能直接在生产代码中人工热改。

## 7. 产品运营能力

- 用户反馈和客服入口；
- 内容错误一键举报；
- 公告、维护和版本更新；
- 学习数据报表；
- 邮件/短信服务的国内可达性；
- 适合中国网络环境的统计和监控；
- 收费时增加订单、发票、退款和消费者权益流程。

## 8. 上线阶段

### 阶段 A：现在到 PET/FCE 完成

- 冻结 KET 交互基准；
- 完成 PET/FCE 数据模型和组件复用；
- 建立题库完成矩阵、来源台账和授权台账；
- 开始域名、主办主体、版权和业务许可确认；
- 把媒体迁移方案、后端模型和账号体系写成技术设计。

### 阶段 B：小范围内测

- 完成账号、数据库、后台、同步、备份和监控；
- 仅使用已获授权的内容；
- 邀请少量真实学生测试；
- 验证中国大陆不同网络和设备下的音频、图片与性能；
- 完成隐私、未成年人、安全和客服流程。

### 阶段 C：正式发布

- 备案/许可和页脚信息齐全；
- 权利审查通过；
- 安全测试和恢复演练通过；
- 生产监控、客服、回滚和应急负责人到位；
- 再开放付费或大规模推广。

## 9. 当前可立即开始的工程任务

1. 设计跨级别统一题库 schema；
2. 把浏览器存储封装成 repository 接口，为将来替换为 API 做准备；
3. 设计学生、家长、教研、管理员的权限模型；
4. 建立资源 manifest，去重并为音频/图片计算哈希；
5. 建立题库来源与授权台账；
6. 新增端到端测试覆盖登录、练习、交卷、错题、生词和跨设备同步；
7. 为隐私、协议、注销和数据导出预留页面与接口；
8. 将 CAE/CPE 从产品路线和未来正式级别选择器中移除。
